## A. 보안 (5)

### A-1. SQL 인젝션 — 회원정보가 통째로 나갈 수 있다
- 사용자 입력을 SQL·필터 문자열에 그대로 이어 붙이지 않는다.
- Supabase `.or()` / `.filter()` 문자열에 검색어를 넣을 때는 특수문자(`,` `(` `)` `.` `%` `*`)를 걸러낸 뒤 넣는다.
- DB 함수에서 동적 SQL(`EXECUTE`)은 `format('%I', …)` / `USING` 바인딩만 쓴다.
- 모든 테이블에 RLS를 켠다. 뚫려도 남의 데이터는 못 보게 하는 마지막 방어선이다.
- 확인: `.or(\`` · `ilike.%${` · `EXECUTE ` 검색, Supabase 보안 어드바이저.

### A-2. 무차별 대입 공격 방어 — 시도 횟수 제한
- 로그인은 Supabase Auth 시도 제한을 켜 둔다. 비밀번호 로그인이 있으면 CAPTCHA 검토.
- PIN·전화번호 뒷자리·수정 코드처럼 **짧은 번호로 본인 확인하는 모든 곳**은 5회 실패 시 잠금.
- 횟수는 서버(DB)에서 센다. 화면에서만 세면 우회된다.

### A-3. 비밀번호 해시 — 원문 저장 금지
- 비밀번호는 Supabase Auth에만 맡긴다. 우리 테이블에 비밀번호 컬럼을 만들지 않는다.
- PIN·수정 코드는 해시(`crypt()` + `gen_salt('bf')`)로 저장한다.
- 로그·에러·알림에 비밀번호나 PIN이 찍히지 않게 한다.

### A-4. 파일 업로드 검증 — 항목별 허용 형식과 크기
- 화면의 `accept="image/*"`는 보안이 아니다. **Storage 버킷 설정**(`allowed_mime_types`, `file_size_limit`)으로 막는다.
- 엑셀·CSV는 서버에서 행·열 수 상한을 두고 읽는다.
- 저장 파일명은 무작위로 만든다(사용자 입력 파일명 그대로 사용 금지).

| 항목 | 허용 형식 | 최대 크기 |
|---|---|---|
| 프로필·작업 사진 | jpg, png, webp | 5MB |
| 상품·후기 이미지 | jpg, png, webp | 5MB |
| 명단 가져오기 | csv, xlsx | 2MB |

(값은 초안. 프로젝트별로 확정한다.)

### A-5. 공개된 취약점 점검 — 의존성
- 배포 전 `npm audit --omit=dev`. high 이상은 고치고 배포한다.
- GitHub Dependabot 알림을 켠다.
- 새 패키지는 설치 전에 이름 철자와 출처를 확인하고, 대표 승인 후 설치한다.
